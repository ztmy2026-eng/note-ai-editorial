# 編集部の共通ルール(全Agentが必ず守る)

1. **事実・推測・意見・体験を区別する。**
   - 事実=出典(URLと日付)がある情報。出典のない断定は事実と書かない。
   - 推測=AIの推論。必ず「推測」と明記する。
   - 体験=筆者(ユーザー)が実際に経験したこと。
2. **体験を創作しない。** 筆者の体験・実践結果・数字が必要な箇所は、作り話にせず
   `【要入力:何を書いてほしいか】` という空欄にする。
3. **情報源を記録する。** URL・公開日・取得日を残す。
4. **著作権・個人情報。** 他者の文章を長く転載しない(引用は短く、出典明記)。個人が特定できる情報は書かない。
5. **お金・投資の記事。** 「必ず儲かる」等の断定をしない。リスクと「個人の経験であり助言ではない」旨を入れる。
6. **公開・投稿・送信はしない。** 成果物をファイルに保存するだけ。公開判断は人間が行う。
7. **文体(仮置き。変更可)。** です・ます調、読者に語りかける、親しみやすく具体的。
   「いかがでしたか」「まとめると」の連発、空虚な総括、過度な箇条書きなど、AIっぽい文章を避ける。
8. 事実と数字は、リサーチ成果物にあるものだけを使う。無いものを足さない。

## 自動モード(config/limits.yaml の auto_approve: true のとき)
人が途中で空欄を埋められないため、次を守る。
- 【要入力】や「(要確認)」を**残さない**。筆者が確定させていない体験・数字は書かずに省き、確定情報(author_notes.md など)と説明用の架空例・チェック表で価値を出す。
- 外部の統計や数字は、取得できた出典(URLと日付)があるものだけを使う。確認できないものは使わない。
- 筆者の意見を創作しない(「私は〜と考えています」は、筆者の回答にあるときだけ)。
- 迷ったら書かずに省く。省いて記事が成立しないなら、その企画は止まる(検品で止まるのが正しい動作)。

## 節約・金融・保険の記事(誤情報の影響が大きい分野)
- 特定の保険商品・金融商品・会社名の推奨や勧誘をしない。比較は「何を見るか」の一般的な観点にとどめる。
- 保障内容・保険料・給付の条件・利回り・税制などは、確認済みの出典(URLと日付)があるものだけ書く。無ければ数字や条件を書かず、「契約前に約款・重要事項説明書・窓口で確認する」と案内する。
- 節約の効果額を断定しない(「年◯円得する」等)。個人の状況で変わることを明記する。
- 「必ず」「絶対」「損する」「得する」などの断定・あおりをしない。
- 記事に「助言ではなく一般的な情報」「判断は自己責任で、必要に応じて専門家に相談」の趣旨を入れる。

## 週次企画から作る記事(runs/<ID>/00_plan.md がある実行)
- `config/weekly_policy.md` に従う。上の「自動モード」と食い違うところは weekly_policy.md が優先。
- 特に、筆者の体験の欄(「僕自身の失敗」など)は `【要入力:◯◯】` として残す(承認2はこの印が残る間は止まる。あなたが埋めて `approve-publish` するまで公開準備済みにならない)。
- 未確認の数字・事実は「(要確認)」も含めて残さない(書かずに省く)。
