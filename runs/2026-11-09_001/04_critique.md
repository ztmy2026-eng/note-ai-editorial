# 批評: 「安いから買っとこう」で、物が増えてない?

## 問題点
1. 【重大】「あるある」の数(導入2か所・失敗2・失敗3・つまずき2か所) — 「そんな人もいると思います/いるかもしれません」が本文に6回あります。weekly_policy.md では「あるある」は1記事に2〜3か所までで、超えています。同じ締め方が何度も続くので、読者には型に当てはめた文章に見えます。 → 残すのは導入の「つい2個目をかごに入れる」、失敗2の「同じ物が2つ出てきた」、失敗3の「冷蔵庫の奥で存在を忘れる」の3つまで(このうち1つは言い方も変える)。導入2文目の「セールのページを開いてから…」は「セールの前に決める4つの順番」の節の冒頭へ移し、普通の説明文にします。つまずき節の3項目は「〜しがちです」「〜で止まることがあります」など、あるある形でない言い方にします。
2. 【重大】失敗2「食品表示基準では、消費期限は「腐敗や品質の劣化で…」、賞味期限は「品質が十分に保たれる期限」とされています[S3]」 — 01_research.md と執筆メモの両方に「[S3]は原本を開けず、検索結果の要約で確認」とあります。それなのに「」に入れて引用の形にしています。食品表示基準の実際の条文はもっと長く(「定められた方法により保存した場合において…」など)、この「」の中身は条文どおりの文言ではありません。未確認の文言を引用として載せることになります。 → 「」を外して、「消費期限は、安全に食べられる期限。賞味期限は、品質が保たれる(おいしく食べられる)期限です[S3]」のように、言いかえだと分かる形にします。原本を開けたら、そのときだけ引用に戻します。
3. 【重大】時期の話がない(導入〜「セールの前に決める4つの順番」) — 01b_trends.md の結論は「これから年末にかけてセールが続く時期なので、テーマは時期に合う。得の角度を足す」でした。ところが本文には時期の話が一言もありません。PVを集めたい記事で、「いま読む理由」という一番強いフックを使っていません。 → 導入のあいさつの直後に「これから年末にかけて、ネットもお店もセールが続く時期です」と1文入れます(日付・店名・割引率は書かない。トレンドの日程は二次情報で未確認なので、書かなかった判断は正しいです)。「4つの順番」の節の見出しも「セールが始まる前に決める4つの順番」にして、時期とつなげます。
4. 【中】「1,000円の物を3つ…見送ったら3,000円が残ります。逆に、3つとも買って使わなかったら、3,000円が物に変わって、家の中に残ります」 — 「買わなければお金が残る」は当たり前のことで、11-07の方針にある「いくら得・損かまで深掘り」になっていません。「物に変わって家に残る」という書き方も、損なのかどうかがはっきりしません。 → 割引と組み合わせた仮の例にします。例:「仮の例:1,000円の物が30%引きで700円。3つ買うと2,100円で、"得した"のは900円。でも3つとも使わなければ、2,100円がまるごと出ていっただけ。得の900円より、出ていく2,100円のほうが大きい」。つまずき節の「30%引き」ともつながります。計算は前提と一緒に書きます。
5. 【中】タイトル「物が増えてない?」と本文のずれ — タイトルは「物が増える(散らかる・置き場所がなくなる)」の話ですが、本文の中心は食品ロスと期限の話です。「物が増える」に当たるのは、日用品の1段落(28行目)と「置き場所を決める」の1行だけです。タイトルで開いた人(特に、日用品や服・ネット通販で物が増えている人)の期待に応えきれていません。 → 失敗3「置き場所と期限を見ない」を、日用品の話を主役にして書き直します。例:棚の奥のストックは、あると気づかないので、また買ってしまう。それが失敗2につながる、という流れです。そのうえで、食品の期限は後半にまとめます。食品ロスの統計は、導入の1回だけで十分です。
6. 【中】食品ロスの数字の使い方(13行目・44行目) — 224万トンを2回出しています。44行目の「ひとごとではないのかもしれません」は、全国の推計値を読者個人の損に結びつけていて、論理が飛んでいます。リサーチでも「数字は1回にとどめる」とされていました。 → 44行目の段落(「ここでも、家庭系の食品ロスが…」から「(推測)」まで)を消します。13行目の「日用品の公的な数字は見つけられていないので、そちらは数字なしで書きます」は、作業メモが本文に出てしまっているので、これも消します。
7. 【中】26行目「【画像:fig_example.png】※図は計算の前提つきで入れる位置の印」 — 画像の印の後ろに注記がついていて、「単独行で置く」という決まりに反しています。export のときに画像の印として認識されず、本文に注記がそのまま残るおそれがあります。fig_example は企画(plan.yaml)にない図で、figures.json もまだありません。 → 画像の行は `【画像:fig_example.png】` だけにします。図を作らないなら行ごと消します。使うなら figures.json に bar で仕様を書き、図の下(note)に「仮の例。1個500円・2個で800円」の前提を入れます。
8. 【中】同じ文末が3回続く — 11行目「決まります。/残ります。/高くついてしまいます。」、21〜24行目「残ります。/計算になります。/分かれます。」、65行目「とします。/残ります。/残ります。」は、どれも「〜ます。」が3回続いています(weekly_policy の検品項目)。 → 11行目は「使い切れれば、割引はそのまま手元に残る。使い切れなければ、割引は消えて、むしろ高くつきます」のように、体言止めや言い切りを1つ混ぜます。65行目は問題点4の書き直しで解消します。
9. 【軽微】50行目「セールのページを開いてから考えると、画面の「残りわずか」に引っ張られます」 — 出典のない言い切りで、読者全員がそうだと決めつけています。 → 「〜引っ張られやすくなります(推測)」にするか、「『残りわずか』の表示を見ると、急いで決めたくなる」と、場面の説明にとどめます。
10. 【軽微】21〜24行目の「差は500円です」 — 「200円残る」は2個分の値段(1,000円)と比べた数字、「300円多く払う」は1個分の値段(500円)と比べた数字で、比べる相手が違います。それを足して「差は500円」としているので、読者がつまずきます。 → 「差は500円です」を消して、「必要なのが1個なら、割引はむしろ損になる」と言い切るほうが伝わります。
11. 【軽微】本文中の「(推測)」が3か所(28・44・73行目) — ルール上ラベルが要るのは分かりますが、読み物としては硬く、AIが作った感じが出ます。 → 44行目は問題点6で消えます。28行目と73行目は「〜かもしれません」「〜と思います」という推測の言い方がすでにあるので、本文の「(推測)」は外し、執筆メモにだけ残す、という運用にしてよいか、編集長に確認します。外さない場合は、文末にまとめて「(ここは筆者の推測です)」と1回だけ書きます。
12. 【軽微】情報源の番号 — 本文と情報源の一覧で[S1][S3][S4]を使い、[S2]がありません。読者には抜けているように見えます。 → 01_research.md どおりにS2(環境省、前年度233万トンの出典)を一覧に加えます。前年度の数字はS1でも確認できているので、加えない場合は番号をS1〜S3に振り直します。

## AIっぽさ
- 「そんな人もいると思います」「そんな人もいるかもしれません」が6回(問題点1)。一番目立つ型なので、3回以下にして、言い方も変える。
- 「大事なのは、買う前に『この期限までに、自分は食べ切れるか』を考えることです」(36行目) — 「重要です」系の締め方です。「買う前に、『この日までに食べ切れる?』と一度だけ自分に聞いてみてください」と、行動の形にします。
- 「もちろん、〜と言うつもりはありません。ただ、〜」(44行目)、「もちろん、本当に必要で使い切る物なら、買って大丈夫です。このチェックは『買うな』というものではなく…」(67行目) — 先回りの言い訳が2回あり、AIっぽい防御的な文になっています。44行目は消し、67行目は「必要な物は、迷わず買ってOKです」の1文に縮めます。
- 「少し大きな話をすると」(13行目) — つなぎ言葉だけで中身がありません。消して、数字から始めます。
- 「どれも、僕の話ではなく、読者の場面として考えたものです」(71行目) — 編集のルールを読者に説明してしまっています。読者には意味がない文なので消します。
