# 批評: 新人の私がAIに最初に任せた2つの仕事:議事録とメールで「任せていい所・ダメな所」

## 問題点
1. 【重大】「AIに任せていい所・自分で確認すべき所」節(41〜43行目)と全体構成 — 【要入力】以外で読者に渡せる中身が「形を整える作業は任せやすい/日付・数字・決定事項・担当・宛名は自分で確認」だけです。これはAIの入門記事ならどこにでも書いてある一般論です。7節のうち4節の中身が体験次第なので、筆者の回答が「議事録の下書きに使った、少し早くなった」くらいの薄さだった場合、記事全体が「白書の数字+常識的な注意」で終わります。空欄が埋まっても、埋まり方によっては成立しない構造です。 → 筆者の体験に頼らなくても読者に渡せる「具体物」を骨組みの段階で1つ入れてください。たとえば (a) 架空と明記した走り書きメモ → AIの整形出力 → 「ここが危ない」の赤入れ、の3段の実例。(b) 議事録・メールそれぞれのチェック表(「メモに無い決定事項や担当をAIが補っていないか」「日付と曜日が合っているか」「敬称・社名表記」「約束の範囲が勝手に広がっていないか」など、5〜7項目)。こうしておけば、体験は「このチェック表がどう効いたか」の裏付けとして入れられ、空欄の出来に記事の価値が左右されにくくなります。

2. 【重大】数字を使う3節(13行目・21行目・51行目)— 記事の根拠になっている数字がすべて検索要約由来の未確認値で、しかも次の3つの問題が重なっています。(i) 本文に「(要確認)」が8か所、「一次情報での確認は公開前に行います」(15行目)が読者向けに残っていて、このまま出すと信頼を損ないます。(ii) 「業務類型別で議事録・メール作成補助が約7割」の分母(全企業か、利用企業か、回答企業か)が分からないまま、23行目で「多くの会社が**最初に**使い道を見つけたのは定型の文章を作る仕事」と書いています。白書の数字は「多さ」であって「順番」ではないので、「最初に」は根拠のない言い換えです。(iii) 86.4%(業務で利用)と約27%(組織的な取組はない)は、並べると読者には矛盾して見えます(使っているのに取組がない?)。調査対象(企業規模や回答者)が分からないため、「会社の側もすでに使い始めている」(17行目)は一般化しすぎの恐れがあります。 → 公開前に白書本文で数字・分母・調査対象・公表日を確認し、確認できた数字だけを残して「(要確認)」と15行目の注記を消してください。確認できない数字は削ってください(記事の筋は「議事録・メールの利用が多い」の1点だけあれば成り立ちます)。23行目は「最も多く使われているのは定型の文章作りです」に直し、「最初に」は消してください。86.4%と27%を両方使う場合は「使ってはいるが、会社としてのルール作りは追いついていない企業もある」と、二つの関係を1文で説明してください。

3. 【重大】「今日から試すなら、この1つ」節(59行目)と「会社のルール」節の順番 — 締めの節で「AIに『読みやすく整えて』と頼み」と勧めていますが、直前で言った「入力してよいか会社に確認する」が締めでは繰り返されていません。読者の多くは締めだけを実行します。その結果、社内会議の議事録や取引先とのメールを、そのまま個人アカウントのAIに貼る行動を後押しすることになります。情報漏えいは新人にとって取り返しのつかない失敗で、記事の責任になります。 → 締めの手順の1番目を「会社の利用ルールを確認する(無ければ上司に聞く)」にしてください。そのうえで「固有名詞・金額・社名は●●に置き換えてから入れる」「社外秘のメモは入れない」など、入力前にできる伏せ方を具体的に1〜2行入れてください。27行目の要入力に「録音の文字起こし」とありますが、会議の録音には参加者の同意や社内規程の問題もあるので、本文で触れる場合はその注意も添えてください。

4. 【中】導入(3〜5行目)と結論(59行目)が噛み合っていない — 導入の悩みは「メモが走り書きで読めない」「今日中」「同じ日にお礼メールも」、つまり時間がなく材料も不完全という状況です。ところが結論は「まず自分で一度書き切ってから、AIに整えてもらい見比べる」で、時間はむしろ増えます。また、読めないメモはAIにも読めない、という肝心の点に触れていません。 → 導入の悩みに合わせて「読めない箇所は推測させず【不明】と書かせる」「整える前に、自分で決定事項と担当だけ3行で書き出してから渡す」など、時間がない日に使える手順に変えてください。または導入の場面を「時間はあるが質に不安がある」状況に差し替えてください。今は「書き切ってから比べる」が練習法としては良くても、導入で示した読者の痛みには答えていません。

5. 【中】タイトルの「私がAIに最初に任せた」(1行目)— 本文に筆者の体験はまだ1行もありません。筆者が実際に議事録とメールの両方を、しかも「最初に」AIに任せたかどうかは未確認です(02_ideasでも「使ったことがなければ1〜2週間試せるか」と聞いている段階)。どちらか一方しか経験がない、または最初に使ったのは別の用途だった場合、タイトルが嘘になります。 → 筆者の回答を得るまでタイトルは仮置きとし、体験がない場合は02_ideasの案2「議事録とメールだけでいい。新社会人のAI仕事術、最初の一歩」のように、体験を前提にしない形に切り替えてください。体験がある場合も「最初に」が事実かどうかを確認してください。

6. 【中】1節「職場でAIを使うのは、もう特別なことではない」(13行目)— 個人の「利用経験率58.8%」は仕事での利用とは限りません(私生活で1回触っただけも含みうる)。それを「職場で」の見出しの根拠にしています。 → 個人の数字は「個人で使ったことがある人は半数を超えた」と書き分け、職場の根拠は企業側の数字(確認できた場合)だけにしてください。あわせて、7行目「特別なことではなくなってきました」と見出し・17行目の「方向感」が同じことを3回言っているので、1回にまとめてください。

7. 【中】39行目「ここは筆者の体験が中心になる節です。体験が入る前の骨組みとして、考え方だけ先に置いておきます。」 — 編集向けのメモが本文に混ざっています。このまま公開されると、読者には未完成の記事に見えます。 → 削除してください。同じく、68〜71行目の「執筆メモ」と66行目の情報源にある「本文は未取得で検索要約のみ確認」は、公開版では外すか、確認後の表記(公表日・取得日)に書き換えてください。

8. 【軽微】43行目「AIは…会議で実際に何が決まったかは知りません」 — 方向は正しいのですが、新人が本当に引っかかるのは「知らない」ことではありません。「メモに無い決定事項や担当者・期限を、もっともらしく補って書いてしまう」ことです。 → 「AIは、メモに書いていない『誰がいつまでに』を自然に埋めてしまうことがあります。担当と期限は必ず元メモと突き合わせてください」のように、起こる現象として書いてください。

9. 【軽微】51行目「同じ白書では…米国の1.4%と差がある」 — 新人読者にとって米国との比較は行動につながらず、数字が1つ増えるだけです(しかも未確認)。 → 確認できた場合でも「約4社に1社は会社としての取組がない」だけにし、米国比較は削るか括弧書きに落としてください。

10. 【軽微】63行目 CTAが【要入力】で、テンプレが無い場合の代わりが決まっていない — テンプレが無いと、記事の「持ち帰れるもの」がさらに減ります。 → テンプレが無い場合は、問題点1で提案したチェック表をそのまま記事内の配布物(CTA)にしてください。筆者の手持ちが無くても成立します。

## AIっぽさ
- 17行目「数字の細かい部分より大事なのは、方向感です。〜そう考えてよさそうです。」:数字を出した直後に「細かい部分は大事ではない」と言う、AIによくある逃げの総括です。未確認の数字を言い訳しているようにも読めます。→ 削除して、数字の後はすぐに「だから新人が使うこと自体は後ろめたく思わなくていい」という読者への意味に進めてください。
- 51行目「もうひとつ、記事の都合ではなく大切な話です。」:「記事の都合」は書き手の内側の言葉で、不自然です。→「ここは飛ばさないでください。」程度に短くしてください。
- 53行目「決して珍しくなさそうです」:「決して」と「なさそう」で強調と推量がぶつかっています。→「珍しくないようです(推測)」と書くか、数字が確認できたら「4社に1社ほどあります」と言い切ってください。
- 59・61行目「全部やろうとしなくて大丈夫です」「その差を見るだけで、自分なりの『任せていい所』が見えてきます。」:どの記事にも付けられる励ましと抽象的な締めです。→ 締めは具体的な一手(例:「次の議事録で、決定事項と担当の行だけ赤ペンで元メモと照合する」)で終えてください。
- 「〜と考えられます」「〜と考えてよさそうです」「〜なさそうです」の推量が各節にあり、文末が弱く単調です。推測の明記はルール上必要ですが、「(推測)」ラベルや「私の考えでは」に置き換えて、文末は言い切りを混ぜてください。

## 有料記事としての可能性
現状は成立しません。理由は、読者が持ち帰れる具体物(実例・指示文・チェック表・時間の前後比較)がすべて【要入力】の側にあり、骨組みだけでは無料の入門記事と差がないためです。成立させるには、(1) 実際の指示文と、伏せ字にした入力・出力の実例、(2) AIが間違えた具体例と、気づいた方法、(3) 議事録・メール用のチェック表やテンプレ、のうち少なくとも2つが必要です。筆者の体験が薄い場合は、無料記事としてフォローの獲得に使うのが妥当です(推測)。
