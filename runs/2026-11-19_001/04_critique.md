# 批評: AIで毎月の出費を整理する、5分の手順

## 問題点
1. 【重大】記事全体/「4つ目が大事です。…いくら変わるかは人それぞれなので、金額は自分の明細で確かめます。」 — weekly_policy.md の「いまの目的は人を集めること」「着眼点は『得』にする」「当たり前の話にしない」(2026-11-07・11-11)に反する。読み終えて手に入るのが「整理できた」と「確認の習慣」だけで、何がいくら得なのかが一度も出てこない。今の構成は、方針が禁じている「見方の説明で終わる記事」になっている。 → 手順4の直後に「仮の例」と明記した試算を1つ入れる(例:「仮の例:使っていない月額サブスク1件(仮に月○円)を見つけて止めると、年で○円×12。金額はサービスごとに違います」)。試算は計算スクリプトで出し、前提を書く。または、家計調査の全国平均額をe-Statで確認できたら「平均と並べて比べる」使い方を手順に足す(01_research.md では未確認なので、確認できなければ入れない)。本文はおよそ1,900字で、2,500字の上限まで約500字の余裕がある。

2. 【重大】手順1「費目と金額だけを書き写す」と、手順2「AIに…食費・通信費・サブスク・その他に分けて」 — 手順が矛盾している。カードの明細にあるのは店名・サービス名で、費目は書かれていない。読者が費目を書き写せる時点で、分類はもう自分で済ませている。これではAIに頼む意味がなくなり、記事の中心が崩れる。 → 手順1を「店名(サービス名)と金額だけを書き写す/コピーする」に直す。つまずき1の「整理に必要なのは、費目と金額だけです」とまとめの文言も、同じ言い方にそろえる。

3. 【重大】「## 結論」の「AIに任せるのは…分けるところ」と、つまずき2の「サブスクの1件が、食費に分けられてしまう」 — 結論で「分類はAIに任せてよい」と書き、2つ後の節では「分類を間違える例」を出している。読者は「結局、分類も信用できないのか」と戸惑う。さらに、結論のすぐあとの「この線引きだけ覚えておけば大丈夫です」は、根拠のない言い切りになっている。[S1]は個人情報の扱いについての注意喚起で、「並べる・分けるは任せてよい」とは述べていない。 → 結論を「AIには下書き(並べる・分ける)を頼み、分類と合計は自分で見直す」に直す。「大丈夫です」は消す。[S1]は「回答に不確かな内容が含まれることがある」の根拠としてだけ使い、線引きは「筆者の提案」と分かる言い方にする。

4. 【中】タイトル「5分の手順」と手順1「(1〜2分)」 — 1か月分のカード明細とアプリの通知を手で書き写すのは、件数が多い人なら1〜2分では終わらない。5分の根拠が示されておらず、読者が試して「5分で終わらない」と感じると、記事への信頼が落ちる。また、タイトルの「5分」は作業時間なのに、検査では読む時間(read_minutes)として扱われていて、意味がずれている。 → 対象を「毎月決まって出ていく固定費・サブスクだけ」に絞り、件数を小さくして5分を現実的にする。分数は「目安」と書く。タイトルも、方針(2026-10-27「あるある型」「」で鍵の言葉」・2026-11-11「1つの具体的な行動」)に合わせた案を検討する(例:「明細は『名前を消して』からAIに渡す」19字/「AIに家計を任せる前に、名前を消す」17字。どちらも30字以内)。今のタイトル(19字)は字数の条件は満たすが、「整理する手順」は中身が想像しにくく、得も見えない。

5. 【中】まとめ前の「年末年始は、家計を振り返る人が増える時期だといわれています(民間の解説)」 — 出典を言い過ぎている。01b_trends.md の楽天証券の解説は「振り返る時期とされ」までで、「人が増える」という量の主張はない。この出典(URL)は「## 情報源」にも載っておらず、日付も確認できていない。公開は11月19日で、年末年始の呼びかけとしても1か月以上早い。 → 「人が増える」を消して「年末年始は、1年の出費を振り返る時期ともいわれます(楽天証券の解説)」とし、URLと取得日を情報源に足す。時期の一言が不要なら丸ごと消して、「今月の明細が届いたら」に置きかえる。

6. 【中】「僕が調べた範囲では見つかりませんでした」(つまずき2)、「これは、僕がおすすめする手順です」(つまずき3) — 調べたのはAI(リサーチ係)で、持ち主ではない。「僕が調べた」は筆者の行動を作っている。「僕がおすすめする」も筆者の意見を作っている(editorial_rules.md「筆者の意見を創作しない」、weekly_policy.md「体験を作らない」)。 → 「公的な事例は、今回は確認できませんでした」「決める前に公式サイトで確かめる、という順番をおすすめします(この記事の提案です)」のように、主語を「僕」にしない言い方にする。

7. 【中】「あるある」の数と記録 — 読者の場面が5か所ある(冒頭の明細を閉じる、家計簿アプリが続かない、明細を丸ごと貼る、合計が合っていそうに見える、控除をAIに聞く)。方針は「1記事に2〜3か所まで」。また `author_notes.md` が無く、「Claudeの提案(未確認)」の記録が執筆メモにしかない。 → 冒頭の「家計簿アプリが続かなかった」と、つまずき2の冒頭はあるあるの形を外して普通の説明にし、3か所にする。残す3か所は `author_notes.md` に「Claudeの提案(未確認)」として記録する。

8. 【中】つまずき3の2段落目「この記事で紹介した個人情報保護委員会の注意喚起も、2023年の公開時点のものです。…」 — 節の題は「制度の最新情報をAIで信じる」なのに、この段落はPPCの文書が古いという断り書きで、論点がずれている。さらに「控除」「手続きの期限」は、AIで出費を整理する記事の中では話がそれている。 → 断り書きは末尾の※(注意書き)へ1文で移す。節の例は、出費の整理につながるもの(例:「この料金プランは今いくら?」「このサブスクの解約期限は?」をAIに聞いてそのまま信じる)に替えて、「公式の料金ページ・契約画面で確かめる」につなげる。

9. 【中】画像の印 — `figures.json` も `images/` もまだ無い。00_plan.md の fig1 は「確認の順番(タイムライン)」で、01_research.md の案は「個人情報を除く→整理→検算→制度を公式で確認」の流れ。一方、本文の手順は4つ目が「固定費を1つ選ぶ」なので、図と本文の手順が食い違うおそれがある。fig2(チェックリスト)は直後の箇条書きと中身が丸かぶりで、まとめが二重になる。 → fig1 は本文の4つの手順と同じ文言・同じ順で作る(手順は1か所にそろえる)。fig2 を置くなら、まとめの箇条書きは1行の要約にして、図に任せる。どちらの図も、作ったあと1枚ずつ目で見て確かめる。

10. 【軽微】「名前や番号は、最初から入れない。使うAIの規約は、初めて使う前に一度読んでおく。」 — 言い切りの命令形が2つ続き、年上の読者には指示されているように聞こえる(weekly_policy.md「説教口調にしない」)。 → 「名前や番号は、最初から入れないでおくと安心です。使うAIの規約も、初めてのときに一度だけ見ておくとよさそうです。」のように、語尾をやわらげる。

11. 【軽微】次回予告「次回も、毎日の家計につながる身近な話をします。」 — 方針は「翌日の記事テーマを1〜2文で予告」。plan.yaml の11月20日は「家でできる副業、始めやすい順に比べる」。 → 「次回は、家でできる副業を、始めやすい順に比べてみます。」にする。

12. 【軽微】つまずき2「実際の合計が『10,000円』なのに、AIが『9,000円』と答える」 — 仮の例としては分かるが、1,000円ずれると目立つので、「検算で気づける」という主張を裏づける例になっていない。実際に見落としやすいのは、1件の抜けや二重計上。 → 「1件が抜けて合計が少なくなる」「同じサブスクが2回数えられる」のように、目で見て見落としやすい例にする(金額は書かないか、仮の例と明記する)。

## AIっぽさ
- 「手間がないので、つい、ですよね。」 — 読点で区切った相づちが不自然で、テンプレのあるあるに見える。→ 消すか、「手間がかからないので、やりたくなりますよね。」にする。
- 「この線引きだけ覚えておけば大丈夫です。」 — 空虚な安心させ方。→ 消す(問題3)。
- 「4つ目が大事です。」 — 「大事です」で強調するだけで中身がない。→ 「4つ目までやると、整理が『お金が浮く』につながります。」のように、理由ごと書く(問題1の試算とセットにする)。
- 「〜というイメージです。」(つまずき2の最後) — まとめ癖の締め。→ 前の文で終わらせ、この1文は消す。
- 「[S1]」が本文中に5回出る — note読者には意味が分からない記号。→ 本文では「個人情報保護委員会の注意喚起では」と言葉で書き、[S1]の表記は外す(情報源の章で出典は示せる)。
- つまずき1〜3の流れが毎回「あるある→注意喚起の引用→だから○○する」で同じ型 — 単調で、機械的に見える。→ つまずき2は先に起こりうる例を出し、そのあとで根拠を示す、のように順番を変える。

## 有料記事としての可能性
成立しない(方針上も有料記事は作らない)。理由:中身が「個人情報を入れない・検算する・公式で確かめる」という一般的な注意にとどまり、ほかの記事やAIサービスの案内で無料で手に入る。足りない要素は、そのまま使えるプロンプトの文面(コピー用)、読者の明細から「得」を見つける具体例(仮の例でよい)、分類を間違えたときの直し方。無料記事としても、問題1の「得」が無いとPVにつながりにくい。
