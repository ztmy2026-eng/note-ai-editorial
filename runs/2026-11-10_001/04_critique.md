# 批評: 初めてのボーナス、使う前に決める3つ

## 問題点
1. 【重大】「失敗1:入ってから考える」の本文(25〜33行目) — 見出しは「入ってから考える」なのに、中身の5段落は源泉徴収と社会保険料の計算のしくみの説明になっている。weekly_policy の「いまの目的は人を集めること」(2026-11-07)には「仕組みの解説・見方の説明で終わる記事は書かない」とあり、02_ideas も「引かれる項目は1段落にとどめる」と決めていた。11-07に見送った手取りの記事と同じ形に戻っていて、読者が「入ってから考えると何を失うか」が書かれていない → 税と社会保険料の話は2〜3文にまとめる(「ボーナスからも所得税と社会保険料が引かれる[S1][S2]。いくら使えるかは明細の差引支給額で確かめる」)。空いた分には「入ってから考えるとどうなるか」を仮の例で書く。例:「仮の例:使う分を決めないまま、入った週に外食と買い物を重ねると、カードの請求が来る翌月に、予定の支払い分が足りなくなる」。数字を出すなら「仮の例」と書く。

2. 【重大】27行目の国税庁の計算例(前月給与285,454円・賞与389,558円・扶養3人・税率2.042%・税額7,954円)と33行目 — 33行目で「この記事では割合や手取りの目安は書きません」と書いているのに、6行前に税率2.042%を載せていて、記事の中で言っていることが食い違っている。しかも想定読者は初めてボーナスをもらう新卒・20代で、「扶養3人」の例は当てはまらない。「ボーナスの税金は2%くらい」と受け取られるおそれがあり、お金の記事では特に誤解を招く → 27行目の段落はまるごと削る。33行目の「令和9年分以降に改正」の一文も、読者の行動に関わらないので削ってよい(出典欄のS1はそのまま残す)。

3. 【重大】記事全体の「得」の弱さ(49行目の仮の例、51行目) — weekly_policy の 2026-11-07 では、着眼点を「得」にして、「〜しがち」の指摘で止めず「そうするとどうなるか(いくら得・損か)」まで書くことになっている。この下書きで数字があるのは「20万円を10/6/4に分ける」の1か所だけで、分けると何が得なのかは書かれていない。02_ideas の末尾でも「このままだと『いくら得か』が弱い」と指摘されていたのに、手当てされていない → 49行目の仮の例を「分けた場合/分けなかった場合」の比べ方に直す。例:「仮の例:差引20万円のうち、来月のカード請求と年内の帰省で計7万円が決まっていたとする。書き出さずに『使う分6万円』を先に使うと、予備4万円では足りず、貯める分の10万円に手をつけることになる」。これで「書き出す」「分ける」をする意味が読者に伝わる。数字はすべて「仮の例」と書き、全員に当てはまるとは書かない。

4. 【中】タイトル「初めての」と本文が合っていない — 本文には「初めて」ならではの内容が1つもない。ボーナスを何度ももらっている人にも、そのまま同じことが言える。タイトルで「初めて」と絞った読者は、「初回は満額じゃないの?」「明細のどこを見ればいいの?」を知りたいはず → (a)初めての人向けの段落を1つ足す。例:「初めてのボーナスは、支給があるか・いくらかが会社の決まり(就業規則)によって違う。入社前の説明や就業規則を先に見ておく」(01_research の推測欄の範囲。数字は書かない)。明細の「支給額・控除額・差引支給額」の位置を図(fig1)で見せるのもよい。(b)それができないなら、タイトルを予備案2「ボーナスの使い道、先に分けてみる」にする。ただ、weekly_policy の 2026-10-27(「」で読者の口ぐせを入れる・あるある型)にどちらも合っていない。案:「「入ったら考える」で、ボーナスは消えていく」(20字前後)。

5. 【中】結論と本文の順番が食い違っている(11〜13行目と、失敗2・失敗3の見出し) — 結論とチェックリストの順番は「使える額 → 予定の支出 → 分け方」。なのに本文は「失敗2=分け方、失敗3=予定の支出」で、逆になっている。分け方の仮の例(49行目)を読んだあとで「予定の支出が抜けていた」と言われるので、理屈も後ろから前に戻る → 失敗2と失敗3を入れ替える(「予定の支出を忘れる」を2番目にする)。こうすると、上の3で書いた「書き出していない予定の支出が、使う分を食う」仮の例も自然につながる。

6. 【中】51行目「使う分の枠が決まっていれば、『今日だけならいいか』が積み重なっても、その枠の中で収まります」 — 根拠のない言い切り。しかも74行目の「あるある」で「分け方を決めたのに、その日の気分で変えてしまう」と書いていて、自分で打ち消している → 「枠が決まっていれば、超えたときに気づきやすくなります」くらいに弱める。または「使う分は別の口座や封筒に移しておくと、枠を守りやすい」のように、守るための具体的なやり方を1つ足す(一般的な工夫として書く。数字は出さない)。

7. 【中】47行目「予備の分」の決め方 — 「予定外の出費用」と「ちょっと贅沢したくなったとき用」を同じ枠に入れているので、「使う分」と「予備の分」の違いがはっきりしない。贅沢に使ってしまえば、予定外の出費に回すお金がなくなる。3つに分ける理由の説明に穴がある → 予備は「予定外の出費用」だけにする。贅沢は「使う分」に入れる。または、予備は「年明けまで残っていたら使ってよい」のように、使ってよい条件を書く。

8. 【中】100行目の次回予告「年末が近づく前に見ておきたい、身近な出費の話」 — 週次企画(plans/2026-11-09/plan.yaml)の11-11は、投資をまだ始めていない人向けの記事(「「いつか始めよう」のまま、1年たってない?」)で、予告と中身が違う。しかも「ボーナスの貯める分を、どこに置くか」から自然につなげられるのに、その機会を使っていない → 「次回は、『いつか始めよう』と思ったまま、まだ投資を始めていない人に向けて、始める前の確認を一緒に見ていきます」に直す(勧誘や断定はしない)。

9. 【中】15行目の免責が導入の真ん中にある — 結論を言った直後に「助言ではなく〜自己責任で〜専門家に相談」と固い文が3文続き、スマホで読むと、ここで読むのをやめる人が出る。fig1 より前に置く必要はない → 「ボーナスがあるか・いくら出るかは会社によって違います」の1文だけを導入に残す。免責の文は、まとめの直前か情報源の直前に移す(editorial_rules の「入れる」は、入っていれば満たせる)。

10. 【軽微】7行目「使い道は決まっていないことが多いお金です」 — weekly_policy の「あるある」の節にある、「多い」の割合断定の禁止に当たる → 「使い道は決めないまま、ということもあるお金です」に直す。

11. 【軽微】21行目「これは僕の体験ではなく、一般的にありそうな場面として書いています。」 — 執筆メモに書くべき内輪の断り書きが、本文に出てしまっている。読者は「誰の話?」と引っかかる。前の文がすでに「〜という人もいるかもしれません」の形なので、この断りはいらない → 削る。

13. 【軽微】55〜57行目「〜自然です。」「〜すでに決まっている支出です。」「たとえば、こんなものです。」 — 「です。」で終わる文が3回続いている(weekly_policy の文章の検品に反する) → 3文目を「たとえば、次のようなものがあります。」にする。または2文目を「〜支出のほうです。」でなく「〜支出が抜けやすいところ。」のような体言止めにする。

## AIっぽさ
- 「そこでおすすめなのが、〜です」(41行目) → 年上の読者にすすめる口調になっている。「そこで、最初から3つに分けておく方法があります」に直す。
- 「大事なのは、割合そのものより、〜ことです」(51行目) → 「大事なのは〜」で結ぶ形はAIの文の定番。「割合より先に、枠を決めておくことのほうが効きます」とするか、削って次の文から入る。
- 「(これは推測です)」(39行目)、「と考えられます(推測です)」(76行目) → 本文の中で「推測」と言うのは機械的で浮いて見える。しかも76行目は「考えられます」と「推測です」の二重の言い方。区別は執筆メモで済んでいるので、本文は「〜かもしれません」「〜と思います」の言い方だけにする。
- 「どれも、ありそうな場面だと思います。続けるコツは、完璧に決めようとしないことです。」(76行目) → まとめ方がAIの定型。「全部やらなくて大丈夫です。まずは来月の支払いを書き出すところだけ」と短く言い切って、次に進む。
- 「これはあくまで説明用の仮の例で、この割合が正解という意味ではありません。人によって、貯めたい額も、使いたいものも違うからです。」(49行目)と、まとめの「この記事の数字は仮の例」(96行目) → 同じ断りが2回ある。まとめのほうを削る。
- 「〜ということになりがちです」「〜しがちです」(21・64行目) → 同じ語尾を繰り返している。1か所は「〜ということもあります」に替える。

## 有料記事としての可能性
成立しない。そもそも weekly_policy で「有料記事は作らない」と決まっているので、検討の対象外。仮に有料にするなら、次の3つが足りない。(1)初めての人だけが得られる情報(初回の支給、明細の見方を図で)。(2)「分けると、分けない場合に比べてどうなるか」を示す具体的な比べ方。(3)筆者自身の分け方の実例。いまは体験欄がなく、一般論とチェックリストだけなので、無料の記事で読める範囲を出ていない。無料の記事としても、上の1〜3(仕組みの説明が長い・得が書かれていない)を直さないと、人を集める目的には弱い。
