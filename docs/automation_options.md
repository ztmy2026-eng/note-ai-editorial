# 自動実行の比較:クラウド / Windows PC / GitHub Actions

前提:**APIキーなし**(Claudeの有料プランのログインで動かす)。投稿は常に手動。
このページの内容は、Claude Code公式ドキュメントの調査(2026-10-03)に基づきます。確認できなかった点は「**未確認**」と書いています。

## 結論(おすすめ)

**最初の定期実行は「クラウドのRoutines(ルーティン)」を1日1回。** PCの電源に関係なく動き、APIキーが不要で、いまのこの仕組みにそのまま載せられるからです。
Windows PCの定期実行は、予備にとどめます。GitHub Actionsは、今は選びません(理由は下の表)。

## 費用について(正直な話)

- **追加の契約が不要**でも、**無料ではありません**。いま契約しているClaudeプランの「使える量」を使います。
- 具体的な「1記事あたり何円・何%」は、**公式ドキュメントに数字がなく、推測もできません**。実際に回して、使用量の画面で測るのが確実です。
- 使いすぎを防ぐ仕組みは、すでに入れてあります。1日の上限は `config/limits.yaml` で決めます。
  - 実行数:3 / Agent作業数:30 / 未投稿の公開準備済み記事:3
  - 目安:1記事で、リサーチ・企画・執筆・批評・修正・SNSの**6作業前後**です。30作業なら、うまくいけば**1日4〜5本が上限**になりますが、実行数の上限(3)が先に効きます。
- 最初の1週間は、上限を小さめ(例:1日1本)にして、使用量を見ることをおすすめします。
- 上限に達したときに「従量課金に切り替えるか」は、プランの設定(Usage credits)です。**勝手に課金されないよう、切り替えは有効にしないでください。**

## 「承認なし」で回すときの安全策

- 承認1〜3は自動で通りますが、機械の検品は**人間の承認と同じ条件**で効きます。未確認の数字や空欄が残っていれば、記事はそこで止まります。
- 自動で通した記録には `by: auto` が残ります。
- **noteやSNSへの投稿は、設定に関係なく常に手動**です。このシステムには送信機能がありません。
- 未投稿の記事が3件たまると、新しい記事を作るのを止めます(読み切れない在庫を作らないため)。投稿したら `mark-posted` で記録してください。
- 品質が落ちた場合は、`briefing` の「品質・コストのシグナル」に出ます(検品不合格の回数、やり直し回数)。

## 進め方(おすすめの順番)

1. **段階2(半自動)**:Claude Codeで `/daily-run` を**手動で1回**実行する。上限・承認なしモード・画像の動作を確認する。使用量も測る。
2. **段階3(定期実行)**:クラウドのRoutinesで、`/daily-run` を**1日1回**(朝)に実行する。最初の1週間は上限を絞る。
3. **段階4(常時)**:様子を見て、本数と時刻を調整する。「24時間ずっと動かす」ことはしない。1日1回の短い実行を重ねる。

- 1記事あたりの実際の使用量。
- Windows PCでの画像作成の動作。
